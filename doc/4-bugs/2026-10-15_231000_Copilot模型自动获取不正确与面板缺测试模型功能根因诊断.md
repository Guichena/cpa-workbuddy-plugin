# Copilot 模型自动获取不正确（落盘兜底清单遮蔽上游 57 模型）与面板缺测试模型功能根因诊断

- Bug 编号：`BUG-COPILOT-MODELS-STALE-DEFAULTS-20261015`
- 发现时间：2026-10-15 23:10（用户报告 + 截图）
- 影响版本：copilot-provider 0.1.0 / 0.1.1 / 0.1.2（全版本存在）
- 严重度：中（功能可用但模型清单严重失真，用户无法使用上游真实新模型）

## 1. 用户报告

1. **面板没有模型测试**：参考其他插件，应有手动测试模型的功能。
2. **模型的获取应该有问题**：自动获取的模型不对，应该通过接口自动获取到可用的模型。

截图证据：
- 插件面板账号卡片显示「模型数 **5**」，模型弹窗列出 `gpt-4.1` / `gpt-4o` / `claude-sonnet-4` / `o4-mini` / `gemini-2.5-pro`。
- 宿主「认证文件管理」中该账号的模型列表同样只有这 5 个。

## 2. 根因

### 2.1 直接原因：落盘兜底清单遮蔽上游动态发现

`copilot/authfile.go` 在创建账号时把**兜底清单**写进账号文件的 `models` 字段：

```go
// saveAccount (authfile.go:441)
Models: append([]string(nil), defaultModels...),
// saveTokenAccount (authfile.go:480)
Models: append([]string(nil), defaultModels...),
```

而 `copilot/models.go:145-163` 的 `authModelsForIndex` 优先读取该字段，**只要非空就立即返回**：

```go
if len(acc.Models) > 0 {
    return acc.Models          // ← 永远命中，fetchUpstreamModels 永不执行
}
models, errFetch := fetchUpstreamModels(context.Background(), acc)
```

`fetchUpstreamModels` 是唯一调用上游 `/models` 的入口，因此动态发现能力被完全旁路。

### 2.2 三个放大面

| 出口 | 代码位置 | 后果 |
| --- | --- | --- |
| 面板 `/accounts` | `management.go:248-251` | 卡片「模型数」恒为 5；`/models` 弹窗恒为兜底 5 个 |
| 宿主 `model.for_auth` | `main.go:319` → `authModelsForIndex` | 宿主按账号注册的模型恒为兜底 5 个 |
| 宿主 `model.static` | `main.go:303/312` → `allConfiguredModels` | 兜底清单被并入全局模型目录（`models.go:169-171`），污染跨 provider 路由选模 |

### 2.3 生产取证（2026-10-15 23:2x，只读）

- **插件对外**：宿主 `/v1/models` 中 `owned_by=copilot-provider` 仅 5 个（`gpt-4.1` / `gpt-4o` / `claude-sonnet-4` / `o4-mini` / `gemini-2.5-pro`）。
- **上游真实**：以生产账号令牌请求 `https://api.individual.githubcopilot.com/models`，返回 **57 个模型**，其中 `capabilities.type == "chat"` 的 **53 个**，包含 `claude-fable-5.1`、`gpt-6-sol`、`gemini-4-argon`、`kimi-k3` 等插件完全未暴露的模型。
- **账号文件**：生产 `copilot-f13aadb583ef01ba.json` 的 `models` 字段 = 兜底 5 个（落盘证据）。

### 2.4 附带发现：`dynamic_models` 配置项是死开关

`Config.DynamicModels`（`main.go:90`）在 `configurePlugin`（`main.go:409-411`）被解析赋值，但**全仓库无任何读取点**（`grep -rn "DynamicModels"` 仅命中定义与赋值两处）。面板暴露给用户的 `dynamic_models` 开关不产生任何行为。

### 2.5 问题 2 根因：功能缺失

`copilot/management.go` 的路由表（`managementRegistration`）与 `handleManagement` 的 switch 分支中**均无 `/test-active`**；`panel.html` 的账号卡片动作区只有 `刷新额度` / `模型` / `启用|禁用` 三个按钮。对比其他插件：

| 插件 | `/test-active` 注册 | 面板「测试」按钮 |
| --- | --- | --- |
| workbuddy | 有（`management.go:165/226`） | 有（模型选择弹窗 + 结果就地展示） |
| qoderwork | 有 | 有 |
| traework | 有（`active_ping.go:349`） | 有 |
| zcode | 有（`active_ping.go:81`） | 有 |
| **copilot** | **无** | **无** |

## 3. 上游 `/models` 契约（本轮取证，2026-10-15）

响应条目结构（关键字段）：

```json
{
  "id": "gpt-5.4",
  "name": "GPT-5.4",
  "object": "model",
  "vendor": "openai",
  "capabilities": { "type": "chat", "family": "gpt-5.4", "streaming": true, "tool_calls": true, "vision": true },
  "policy": { "state": "disabled", "terms": "..." },
  "model_picker_enabled": false,
  "model_picker_category": "powerful",
  "tokenizer": "o200k_base",
  "type": "chat"
}
```

实测分布（免费档账号）：

| 维度 | 分布 |
| --- | --- |
| `capabilities.type` | `chat` 53 / `embeddings` 3 / `completion` 1 |
| `policy.state` | `disabled` 21 / 无该字段 25 / `enabled` 11 |
| `model_picker_enabled` | **全部 false**（57/57，对免费档不可用作过滤依据） |

**过滤判据**：`capabilities.type == "chat"` 且 `policy.state != "disabled"` → 32 个；其中仍需剔除内部工具项 `copilot-search-*` / `exec-agent-*` / `trajectory-compaction`（7 个，调用对话接口必报错）→ **25 个可用对话模型**。

注意：`model_picker_enabled` 全为 false，**不能**用作可用性过滤；`policy.state` 才是账号级可用性判据。

## 4. 修复方案

### 4.1 模型发现链路（问题 2）

1. **落盘不再写兜底清单**：`saveAccount` / `saveTokenAccount` 的 `Models` 字段置空，避免遮蔽动态发现。
2. **`authModelsForIndex` 反转为动态优先**：账号文件里的 `Models` 仅在动态发现失败时兜底（对齐 workbuddy 的 `resolveModels` 优先级链：动态 > 配置 > 静态兜底）。
3. **`fetchUpstreamModels` 按上游契约过滤**：只保留 `capabilities.type == "chat"` 且 `policy.state != "disabled"`，并剔除内部工具项。
4. **落地 `dynamic_models` 开关语义**：显式 `false` 时跳过上游请求直接用配置/兜底清单。
5. **写回账号文件**：动态发现成功后把真实清单写回 `models` 字段，使面板与宿主按账号注册都拿到真实值。

### 4.2 测试模型功能（问题 1）

新增 `POST /test-active`，参考既有插件成熟策略：

- 流式请求 `stream: true, max_tokens: 1`，收到首个有效输出帧立即返回（TTFT 级），后台异步关流；
- 拦截 HTTP 200 下的 `event: error` / JSON `error` 字段，不盲判首包成功；
- 面板账号卡片新增「测试」按钮 → 模型选择弹窗 → 结果就地展示（对齐 workbuddy 交互）。

## 5. 验证

### 5.1 单元测试（`copilot/models_discovery_test.go`，7 例）

- `TestIsChatCapableModelKeepsRealChatModel` — 真实对话模型保留（含 policy 字段缺省形态）
- `TestIsChatCapableModelFiltersUnusable` — 剔除 embeddings / completion / `policy.state=disabled` / 三类内部工具项
- `TestIsInternalToolModelRequiresFireworksVendor` — 内部工具项判定必须同时满足 vendor 条件（防误伤真实模型）
- `TestDetectStreamErrorInterceptsBusinessError` — `event: error` 与 JSON `error` 字段被识别；正常帧与 `[DONE]` 不误报
- `TestTruncateForLogBoundsOutput` — 错误文本截断边界
- `TestReadFirstSSEFrameReadsCompleteFrame` / `HandlesEmptyAndUnterminated` — 首帧按 SSE 边界读取（含 >512 字节超长帧）
- `TestPingUpstreamOnceDetectsOversizedErrorFrame` / `AcceptsNormalStream` / `RejectsHTTPError` — 走真实 HTTP 的端到端探活判定

### 5.3 生产真实数据验证（只读）

- **过滤判据**：以生产账号令牌请求上游 `/models`，57 条经过滤得 **25 条**可用对话模型（`gpt-5.4-nano`、`kimi-k3`、`claude-haiku-4.5`、`gpt-4o` 等），内部工具项与 `policy.state=disabled` 条目全部剔除。
