# WorkBuddy AI 国际版「授权成功但未完成注册致无可用额度」根因诊断与修复

- Bug 编号：BUG-WBAI-REGISTRATION-GAP-20261015
- 发现时间：2026-10-15（北京时间）
- 影响范围：workbuddy-ai-provider（WorkBuddy AI 国际版）全部新授权账号
- 严重级别：高（新账号授权后完全无可用额度，功能不可用）
- 状态：**已定位 / 已修复 / 生产实证通过**

## 1. 现象

新账号通过插件 OAuth 授权后，面板显示 `status: active`、`disabled: false`，但：

- `plan` 为空字符串（正常账号为 `trial`）
- `credits` 为空或 0，无法承载推理
- 生产实例：`wivexoj236`（uid `b7e4db75-6fd4-4aee-aca8-0d2f849cc111`，2026-10-15 14:41 授权）

对比同期正常账号（`luode0320`、`luode0321-ios-git` 等）`plan: trial`、额度 300–380，可正常路由。

## 2. 根因

### 2.1 直接原因：登录页按 platform 跳过注册地步骤

插件在 `workbuddy-ai/main.go:81` 以 `platform=CLI` 请求 `POST /v2/plugin/auth/state`，上游返回的 `authUrl` 形如：

```
https://www.workbuddy.ai/login?platform=CLI&state=<uuid>
```

官方登录页（CDN `download.codebuddy.ai/web/login/<hash>/assets/`）主组件 `index-BoJ3AJkv.js` 中存在如下分支：

```js
const m = platform.toLowerCase() === "cli";
if (account.type === PERSONAL && !account.areaInfoComplete && !m) {
    window.location.href = `/login/register/user/complete?...`;  // cli 不跳
}
```

**插件传入的 `platform=CLI` 命中该等值判断，官方前端主动跳过注册地填写页**，导致账号以 `areaInfoComplete=false` 落盘。

### 2.2 后果链

`areaInfoComplete=false` → 云账号未注册 → 上游不分配额度池 → `plan` 为空、无可用积分。

实测上游 `GET /auth/realms/copilot/overseas/user/register?userId=<uid>` 对未设注册地的账号返回：

```json
{"code":500, "msg":"register failed:register region required"}
```

即上游明确要求「先设注册地，才能注册云账号」。

### 2.3 佐证：`platform` 是自由字符串

实测 `platform` 取 `CLI` / `workbuddy` / `web` / `desktop` / `ide` 均返回 `code:0`，仅被原样回显进 `authUrl`（空值才报 `10001:platform is empty`）。差异**只在官方前端是否跳注册地页**，与端点鉴权无关。

## 3. 取证过程（生产只读探测）

| 步骤 | 调用 | 结果 |
| --- | --- | --- |
| 1 | `GET /console/accounts`（Bearer + `X-Domain`） | `areaInfoComplete: false` |
| 2 | `GET /auth/realms/copilot/overseas/user/register?userId=<uid>` | `code:500 register failed: register region required` |
| 3 | `POST /billing/area/get-user-area-info` | 返回出口 IP 地区 `IOS2: SG`（无需鉴权） |
| 4 | `POST /billing/area/get-country-code` | 返回国家列表含电话区号（无需鉴权） |
| 5 | `POST /console/login/account`（Bearer，提交注册地） | `code:0 OK`，`areaInfoComplete` 翻转为 `true` |
| 6 | 重试云账号注册 | `code:200 register success` |
| 7 | `POST /v2/billing/meter/get-user-resource` | 额度 `0 → 350`（Bonus Pack 250 + Free Plan 100） |
| 8 | 插件 `/credits` | `plan: "" → "trial"`，`total_remain: 350` |

**关键结论**：`POST /console/login/account` **接受 Bearer token**（非仅浏览器 cookie），补注册链路可在插件端全自动完成。

## 4. 补注册契约

| 用途 | 端点 | 鉴权 | 备注 |
| --- | --- | --- | --- |
| 注册态判据 | `GET /console/accounts` | Bearer + `X-Domain` | `data.accounts[].areaInfoComplete` |
| 地区推导 | `POST /billing/area/get-user-area-info` | 无需 | 按请求出口 IP；`data` 为二次编码 JSON |
| 国家列表 | `POST /billing/area/get-country-code` | 无需 | `{"filterForbidden":1}`；`data` 二次编码 |
| 提交注册地 | `POST /console/login/account` | Bearer | body `{"attributes":{"countryCode":["65"],"countryFullName":["Singapore"],"countryName":["SG"]}}` |
| 注册云账号 | `GET /auth/realms/copilot/overseas/user/register?userId=<uid>` | Bearer | 成功码 `code:200`（非 0） |
| 领试用包 | `POST /billing/ide/trial` | Bearer | 已领返回 `code:14051` |

**口径细节**：

- `countryCode` 取**电话区号字符串**（如 `"65"`），不是 ISO 码。
- `countryName` 取 `IOS2`（如 `"SG"`）。
- CN 按官方前端口径映射为 `HK`。
- 云账号注册端点的成功码是 `200`，其余端点多为 `0`，判定需兼容两者。

## 5. 修复方案

**采纳方案**：插件端 API 直连补齐注册链路，注册地按出口 IP 自动推导（用户零交互）。

### 5.1 新增 `workbuddy-ai/registration.go`

- `wbAPICall` — 以账号 Bearer 凭证调用 console/billing/auth 端点的通用入口
- `decodeNestedData` — 逐层解包二次编码的 `data` 字段
- `fetchRegistrationStatus` — 查询 `areaInfoComplete`
- `resolveRegistrationRegion` — 按出口 IP 推导地区，CN→HK
- `lookupCountryByISO2` — 从上游列表取完整国家条目
- `submitRegistrationRegion` — 提交注册地
- `registerCloudAccount` — 注册云账号（uid 经 `url.QueryEscape` 转义）
- `ensureAccountRegistered` — 幂等编排：查状态 → 推地区 → 注册 → 尽力领 trial

### 5.2 接入点

- `oauth.go` `handlePollLogin`：凭证返回前 best-effort 调用 `ensureAccountRegistered`，**失败不阻断授权落盘**，通过 `Message` 字段透出补注册结果
- `management.go`：新增 `POST /register` 路由并登记 `mutatingManagementPath`
- `credits_handler.go`：新增 `handleRegisterAccount`；`handleCreditsQuery` 透出 `registered`
- `panel.go`：`wbAccount` 新增 `Registered` 字段；`resolveRegisteredState` 判定注册态（有 plan 直接判已注册、零额外调用）
- `cache.go`：`accountCacheEntry` 新增 `registered *bool` 缓存探测结果
- `panel.html`：新增「未注册」徽标与「补注册」按钮、`isAccountUnregistered` 判定、`registerAccount` 动作

### 5.3 设计约束

- **不伪造成功**：补注册失败时面板如实标注「未注册」，不伪装为已注册
- **零额外调用**：已有 plan 的账号（21/22）不触发注册态探测
- **不阻断授权**：补注册失败不影响凭证落盘，授权本身仍视为成功

## 6. 验证

### 6.1 单元测试（`registration_test.go`，6 例）

- `TestDecodeNestedData` — 二次编码解包与对象原样返回
- `TestResolveRegistrationRegion_MapsCNToHK` — CN→HK 映射
- `TestEnsureAccountRegistered_SkipsWhenAlreadyRegistered` — 已注册零写操作
- `TestEnsureAccountRegistered_CompletesFullFlow` — 完整链路 + 提交体口径（区号 `65` / IOS2 `SG`）
- `TestEnsureAccountRegistered_RegionSubmitFailure` — 提交失败即中断，不继续注册
- `TestRegisterCloudAccount_RequiresUID` — 缺 uid 拒绝

**哨兵反证**：移除 CN→HK 映射后 `TestResolveRegistrationRegion_MapsCNToHK` 精确 FAIL（`got CN`），恢复后全绿——证明测试真实进编译且有判别力。

### 6.2 门禁

- `python scripts/cgo-shim-build.py workbuddy-ai` — build / vet / test 全绿
- 面板内联两段 JS `node --check` rc=0
- 面板事件链一致：`data-action="register"` ↔ `act==="register"` ↔ `registerAccount` 定义

### 6.3 生产实证

账号 `wivexoj236` 经补注册链路后：`areaInfoComplete: false → true`、`registerCloud: register region required → register success`、额度 `0 → 350`、`plan: "" → "trial"`。

## 7. 未覆盖 / 后续

- **未覆盖**：插件自动补注册路径（OAuth 完成后）尚未在**全新账号**上做端到端生产验证；当前生产实证来自手动 curl 补齐 + 单元测试覆盖。需发版后在真实新账号授权流程中确认。
- **合规说明**：注册地由插件按服务器出口 IP 自动提交，属代用户做 billing 地区归属声明；已在面板以「未注册/补注册」显式呈现，并保留人工重试入口。
- **存量账号**：仅 `wivexoj236` 曾处于未注册态（已修复）；其余 21 个账号不受影响。
