# WorkBuddy 国内版成长中心全自动领奖需求

- 需求编号：`REQ-GROWTH-2026-10-15`
- 状态：已接入，实施完成（CYCLE-1 ~ CYCLE-3 闭环，待发布授权）
- 提出时间：2026-10-15
- 来源：本轮 GitHub 开源项目调研 + 用户口头需求「workbuddy 的国内版 github 好像有自动做任务刷积分的开源项目了，不仅仅签到，还可以做任务刷积分」

## 一、背景与目标

### 背景

`workbuddy`（国内版，CN）插件当前只有一条 `daily-checkin` 签到链路，成长中心（成长任务、Buddy 旅行、连登阶梯、补登卡、抽奖、能量盲盒）能力完全缺失。

本轮调研确认 GitHub 上存在成熟的开源实现，覆盖国内版成长中心玩法：

- `88lin/workbuddy-auto-signin`：覆盖成长中心 7 类玩法，服务端 API 直连（本轮端点契约主源，EXT-1）。
- `autumnsentiment/workbuddy-helper`：国内版签到 + 国际版活跃积分（EXT-2）。
- `L0NE-6/WorkBuddy-Daily`：33 项玩法与端点常量，用于交叉印证（EXT-3）。

同时确认 **WorkBuddy 国际版（`workbuddy-ai`）无成长中心**，其积分为按账号活跃发放，不走成长中心端点集合。用户已决策本轮不动国际版。

### 目标

在 `workbuddy`（CN 主插件）新增成长中心客户端与编排层，把外部项目已逆向的 7 类领奖端点接入现有每 4 小时 tick，并在面板 CN 卡片上补一个「成长中心」按钮与一行结果摘要。

## 二、范围

### 范围内

1. 新增 `workbuddy/growth.go`：成长中心端点常量、统一 GET/POST 调用入口、7 类玩法的读/写函数与编排函数 `runGrowthForAccount`。
2. 7 类玩法覆盖：
   - 每日签到状态（复用既有 `fetchCheckinStatus` / `performCheckinCall`，不重写）
   - Buddy 旅行（查状态 → 收礼 → 读取配置 → 再派出）
   - 成长任务（列表 → 接单 → 逐个领奖）
   - 断签补登卡（当月断登且仍有补登卡时每轮最多补 1 张）
   - 连登阶梯兑换（达成档位则兑换最高档）
   - 盲盒抽奖（有次数则每轮最多抽 1 次）
   - Buddy 能量盲盒（可开则开）
3. 配置项 `growth_auto`（默认 `false`），接入既有每 4 小时 tick（`checkinHours` 六槽），与签到共用调度槽。
4. 管理路由 `POST /v0/management/plugins/workbuddy-provider/growth`：单账号（`auth_index`）或全量 CN 扇出（sem=4），返回 `{results, summary}`。
5. 面板 CN 卡片「成长中心」按钮与结果摘要行；Global 卡片不渲染该按钮。
6. 只读探针 `scripts/probe_growth_endpoints.py`（逐端点打印 HTTP 状态与响应顶层字段名，不回显任何凭据原值）。
7. 版本号 `0.15.10` → `0.16.0` 与 CHANGELOG 记录。

### 范围外

1. **不改 `workbuddy-ai/`（国际版）**：本轮调研结论为国际版无成长中心、无传统签到活动；用户已明确「本轮不动国际版」。国际版现有 `checkin` 链路是否失效，另立 Bug / 需求周期。
2. 不改 `qoderwork/`、`qoder-ai/`、`traework/`、`copilot/` 等其它插件。
3. 不做 `L0NE-6/WorkBuddy-Daily` 的小程序链式任务、主题换装、礼包补偿等额外玩法。
4. 不做多账号容器管理（插件已由宿主 auth store 承担）。
5. 不实现国际版「自动活跃对话」能力。
6. 不新增或变更任何数据库表 / 字段。
7. 不执行发布链路（bump registry、dispatch CI、生产 plugin-store 安装）——发布需用户当轮单独授权。

## 三、输入输出

- 输入：宿主 auth store 中的 CN 账号凭据（`~/.antigravity_cockpit/workbuddy_accounts/`）；既有每 4 小时 tick；管理 API 请求（可选 `body.auth_index`）。
- 输出：成长中心上游写操作的真实领奖结果（积分 / 能量 / 任务数）；面板摘要行文本；管理路由 `{results, summary}` 契约。

## 四、约束

1. **协议约束**：成长中心 base 为 `{endpoint}/v2/activity/growth`，`{endpoint}` 取账号所属 billing base（CN `https://www.codebuddy.cn`）。鉴权头与既有 `billingHeaders()` 同族（`Authorization: Bearer` + `X-User-Id` + `X-Enterprise-Id` / `X-Tenant-Id` + `X-Domain`）。
2. **幂等约束**：写操作（accept / claim / depart / redeem / draw / open / makeup-cards/use）幂等性未经上游证实，**一律不重试**，避免重复扣减（补登卡、抽奖次数）。
3. **风控约束**：账号间 1–3s 随机延迟；单账号总时长预算 180s，超时主动放弃并返回已得结果；补登卡每轮 ≤ 1 张、抽奖每轮 ≤ 1 次；复用既有 6 槽 tick，不新增高频调度。
4. **区域约束**：Global 账号无成长中心能力，分支提前返回、不发任何上游请求，批量结果计入 `skipped_global`。
5. **工程约束**：c-shared 动态库（`import "C"`），Windows 无 CGO 环境，本地验证一律走 `python scripts/cgo-shim-build.py workbuddy`。
6. **零新增依赖**：`client_token` 用标准库 `crypto/rand` 生成 UUID v4，不引入 `github.com/google/uuid`。
7. **本地连接红线**：测试与调试只允许使用 local 配置，禁止连接 test / prod；本机无 CN 账号凭据时记为环境阻断，不得用 test / prod 凭据替代。
8. **跨项目只读**：不修改宿主 CLIProxyAPI 与其它兄弟项目任何文件。

## 五、验收条件（AC）

- `AC-001`：`growth.go` 可独立发起全部 7 类端点的 GET / POST 调用；`growthCall` 在 200 + `code:0` 时返回 data、`code!=0` 时返回业务错误、5xx 时 GET 重试且 POST 不重试。
- `AC-002`：`runGrowthForAccount` 按 8 段顺序执行，每段独立 try；单段失败只记入 `Errors`，不影响其余段。
- `AC-003`：写操作幂等保护成立：连续两次调用 `runGrowthForAccount`，第二次不重复调用写端点（server 侧写端点请求计数不增）；补登卡每轮最多 1 张、抽奖每轮最多 1 次。
- `AC-004`：`growth_auto` 解析 `true/1/yes/on` 为开、`false`/缺省为关；`growth_auto: false` 时行为与改动前完全一致（零新增上游请求）。
- `AC-005`：`growth_auto: true` 时 CN 账号在 tick 内触达成长端点；Global 账号零触达。
- `AC-006`：管理路由 `POST .../growth` 单账号 / 批量 / 无匹配账号 / Global 跳过四分支正确；summary 含 `total/success/fail/skipped_global/credits_gained/energy_gained`。
- `AC-007`：面板 CN 卡片出现「成长中心」按钮，点击后 POST `/growth` 并写入摘要行；Global 卡片不出现该按钮。
- `AC-008`：`python scripts/cgo-shim-build.py workbuddy` 的 build / vet / test 全绿。
- `AC-009`：探针脚本 `--readonly` 在真实 CN 账号上逐端点返回 HTTP 200 且顶层字段与契约一致，输出不含任何凭据原值。

## 六、缺口（GAP）

- `GAP-001`：**未关闭（环境阻断）**。本机 `~/.antigravity_cockpit/` 下四个候选凭据目录（`workbuddy_accounts`、`codebuddy_cn_accounts`、`codebuddy_accounts`、`accounts`）均无文件，`python scripts/probe_growth_endpoints.py --readonly` 退出码 1 并提示「未找到可用凭据」。**处置**：按 AGENTS.md「本地连接调试测试红线」，不得以 test / prod 凭据替代；端点契约取自 EXT-1 并用 httptest 桩逐端点断言，真实账号探针待用户在具备本地 CN 账号的环境执行。`AC-009` 因此记为待补。
- `GAP-002`：**未关闭（环境阻断）**。本机 CPA 未监听 `127.0.0.1:8317`，计划中 TASK-3.1 的「local 面板手动点击验证」无法在线执行。**处置**：改用 `test/workbuddy/panel_growth_repro.mjs`（vm + DOM 桩）覆盖按钮渲染、POST 载荷、摘要文案三分支；在线点击验证待 local CPA 可用时补做。`AC-007` 的在线部分记为待补。
- `GAP-003`：成长中心端点未公开文档、全靠逆向，可能随时变更（R1）。**处置**：每段独立 try，单段失败不影响其余；错误分类沿用 `isTransientBillingErr`；契约变更时由 `--readonly` 探针第一时间暴露。**状态：长期风险，未关闭**。
- `GAP-004`：写操作幂等性未由上游证实（R2）。**处置**：写操作一律不重试 + 每轮配额上限 + 账号级互斥锁；若后续探针发现重复扣减，降级为「仅只读展示 + 用户手动触发」。**状态：未关闭**。
