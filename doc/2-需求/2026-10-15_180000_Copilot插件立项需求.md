# GitHub Copilot Provider 插件立项需求

- 需求编号：`REQ-COPILOT-PROVIDER-20261015`
- 状态：已接入，待实施
- 提出时间：2026-10-15
- 来源：用户裁定「GitHub Copilot、Kiro (AWS) 都做，先做 GitHub Copilot provider，验证跑通后再评估 Kiro」

## 一、背景与目标

### 背景

当前仓库（`cpa-workbuddy-plugin`）已有 8 个 CPA 插件，覆盖腾讯 CodeBuddy、Trae、Qoder、Cursor、ZCode 等服务商。用户在评估 `tashfeenahmed/freellmapi`（34 家免费 LLM 渠道聚合）后，确认其中多数渠道为「API key 型免费 tier」，直接配 CPA 原生 OpenAI 兼容上游即可，做插件属重复造轮子。

经全量筛选，符合「OAuth 订阅额度 + 需客户端指纹/私有协议逆向 + 宿主未原生覆盖」三条标准的渠道为 **GitHub Copilot** 与 **Kiro (AWS)** 两家。

### 目标

新增 `copilot-provider` 插件，把 GitHub Copilot 订阅额度（含 Copilot Free）封装为 CPA 的 OpenAI 兼容 Provider，支持多 GitHub 账号池、模型动态发现、流式转发、故障转移与 Web 管理面板，与既有 8 插件同构。

## 二、范围

### 范围内

1. GitHub OAuth Device Flow 登录（`client_id=Iv1.b507a08c87ecfe98`，scope `read:user`）。
2. GitHub access_token → Copilot token 交换与定时刷新。
3. Copilot 上游 `chat/completions` 与 `models` 端点接入（`https://api.githubcopilot.com`）。
4. Copilot 客户端指纹头注入（`copilot-integration-id`、`editor-version`、`editor-plugin-version`、`user-agent`、`openai-intent`、`x-initiator` 等）。
5. 多账号凭据管理、额度查询（`/copilot_internal/user`）、面板展示与账号启停/删除。
6. 故障转移（429/5xx 换号重试）、模型出口 `filterExcludedModels` 治理。
7. 发布链路：CI workflow、registry.json、图标、生产热重载。

### 范围外

1. **Kiro (AWS) 插件**——本轮不实现，仅在 Copilot 跑通后评估立项。
2. Anthropic 协议转译——Copilot 上游本身为 OpenAI 兼容，无需转译。
3. 使用官方 `github/copilot-sdk`（Agent 循环 SDK）——该路径不返回原生 `tool_calls`，需靠文本标记还原，属反面教材，明确排除。
4. Copilot 的 embeddings / 图像 / 视频等非 chat 能力。
5. 修改 CPA 宿主本体。

## 三、输入输出

- 输入：GitHub 账号（经 Device Flow 授权）；CPA 标准 `executor.execute` / `executor.execute_stream` 请求。
- 输出：OpenAI 兼容的 chat completions 响应（流式 SSE 与非流式）；`/v1/models` 模型清单。

## 四、约束

1. **协议约束**：Copilot token 需按 `expires_at`/`refresh_in` 定时刷新；上游 base URL 随账号类型变化（individual → `api.githubcopilot.com`，business/enterprise → `api.<type>.githubcopilot.com`）。
2. **风控约束**：GitHub 有 abuse-detection，过量自动化请求可能致 Copilot 访问临时封停。必须内置请求限速。
3. **工程约束**：c-shared 动态库（`import "C"`），Windows 无 CGO 环境，本地验证一律走 `python scripts/cgo-shim-build.py copilot`。
4. **架构约束**：与既有 8 插件同构；凭据直写物理文件（`writeAuthFileDirect`），不走 `host.auth.save` 以免丢字段。
5. **本地连接红线**：测试与调试只允许使用 local 配置，禁止连接 test/prod。

## 五、验收条件（AC）

- `AC-001`：面板可完成 GitHub Device Flow 登录，显示 user_code 与验证 URL，轮询成功后凭据落盘至 `~/.antigravity_cockpit/copilot_accounts/copilot-<hash8>.json`。
- `AC-002`：Copilot token 能自动刷新，过期前按寿命比例重取，失败有退避重试。
- `AC-003`：`/v1/models` 能返回 Copilot 真实可用模型清单，且响应宿主 `oauth-excluded-models` 配置。
- `AC-004`：`/v1/chat/completions` 非流式与流式（SSE）均可用，流式遇终止帧立即退出并关闭连接。
- `AC-005`：多账号可启停/删除；429/5xx 触发换号重试；额度查询能在面板展示。
- `AC-006`：`python scripts/cgo-shim-build.py copilot` 的 build/vet/test 全绿。
- `AC-007`：发布链路完整（CI 7 平台产物 + registry 同步 + 远端 raw URL 可达 + 生产热重载 `restart_required=false`）。

## 六、缺口（GAP）

- `GAP-001`：**已关闭（2026-10-15 实测 PASS）**。用真实 GitHub 免费账号实测：`copilot_internal/v2/token` 返回 `200` 且 `sku=free_limited_copilot`、`chat_enabled=true`；免费额度为 `chat 200/200`、`completions 1963/2000`；`/models` 返回 57 个模型；`/chat/completions` 非流式与流式均返回 `200`。**结论：插件对 Copilot Free 开放入口成立**，无需付费套餐门槛。证据见 `doc/5-tests/2026-10-15_190000_copilot插件CYCLE-1测试.md` §2.6。
- `GAP-002`：**已关闭（2026-10-15 实测 + 修复）**。实测确认令牌响应的 `endpoints.api` 真实存在且取值为 `https://api.individual.githubcopilot.com`，与按账号类型硬推导的 `https://api.githubcopilot.com` **不同**。已按「存在则以响应字段为准」落地：新增 `StoredAuth.APIEndpoint` 持久化该字段，`resolveCopilotBaseURL` 优先级改为「配置 `base_url` > `endpoints.api` > 按账号类型推导」，并补两个回归用例 + 变异验证。
- `GAP-003`：GitHub 对第三方代理的风控边界未知（是否限速、是否封号）。**处置**：内置限速；生产灰度观察；在 README 与面板明确风险提示。**状态：未关闭**（单账号低频实测无法暴露边界）。
