## 3. 判定说明（两处需记录的口径）

**其一：`panel.html` 中文注释占 2 行**

`comment-rules` 规定说明性注释默认单行、禁止论证式块注释。本轮注释为：

```js
// CN: 签到 button + 领取Pro button
// active=false 有两种成因：show_campaign=true 表示活动被服务端隐藏未下发，
// false 表示账号本不参与该活动；两者按钮文案与提示需区分。
```

第二段 2 行解释「两种成因的语义边界」，属于**代码块语义说明**（非「为什么这样写」的过程推演，也非反事实后果链）。判定为可接受：它说明的是「字段取值 → 业务含义」的映射关系，换人阅读时无法从 `campaignHidden` 变量名推出上游语义。**不构成 `FIX_REQUIRED`**。

**其二：`checkin_summary_test.go` 使用表驱动**

同目录既有测试多为平铺（无 `t.Run` 子测试）。本轮 2 个形态的对照用表驱动更清晰，且 Go 社区标准写法。判定为可接受，不构成风格跳变。
