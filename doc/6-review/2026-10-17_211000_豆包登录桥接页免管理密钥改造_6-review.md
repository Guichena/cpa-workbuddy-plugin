- 逐函数扫描 `login.go`、`login_test.go`、`management.go` 的 `[参数]` / `[返回]` / `最近修改时间` 三项元信息：**零缺失**（测试函数按仓库惯例豁免）。
- `loginBridgeImportHeader` 常量带一段说明「为什么用自定义头而不是 Cookie 头」——这是隐藏约束（宿主把 resource 请求改写为 GET 且不转发 body），符合「只写非显然的 WHY」。
- `handleManagement` 里 `/login/import` 分支上方补了两行说明「为什么必须是 GET」，避免后来者误改成 POST 而静默 404。
- 证据：`STYLE-03：三个 Go 文件函数注释元信息零缺失；两处新增注释均解释非显然约束`

## STYLE-08 语言与框架特异写法

- Go：未使用 `iota`；`loginBridgeImportHeader` 为显式字符串常量。
- 错误处理：拒绝路径统一走 `jsonManagementResponse(400, {error})`，不吞异常；账号已落盘但会话过期的分支仍返回 `ok:true` + 提示，不丢用户凭据。
- 并发：`loginSessionsMu` 的加锁范围仍只包住 map 读写，未在锁内做网络或磁盘 I/O。
- JS：桥接页脚本保持纯静态字符串，provider/state 从 body 的 `data-*` 读取，无 Go 侧拼接（上轮修复的 `API is not defined` 不会复发）。
- Python 探针：`unwrap_response` 同时兼容 `StatusCode` / `status_code` 与 base64 编码的 body，避免因 SDK 字段大小写差异误判。
- 证据：`STYLE-08：无 iota；锁内无 I/O；桥接页 JS 无 Go 拼接；探针兼容字段大小写`
