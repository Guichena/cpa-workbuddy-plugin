## 证据

### 1. 同源脚本取 token

在 `www.coze.cn` 页面上下文执行（真实登录态，`credentials:'include'`）：

```text
POST /passport/token/beat/v2/
  sdk-version: 2
  Content-Type: application/json
  body: {}

响应：HTTP 200
      x-tt-token 响应头存在，长度 355
```

**这关闭了实施文档的 `H-00` 假设**：同源脚本确实能读到 `x-tt-token`，不是静态推断。

### 2. token beat 换 Cookie

插件侧（Node `fetch`，与 Go `http.Client` 等价）以 `x-tt-token` 请求头、不带 Cookie 调用同一端点：

```text
POST https://www.coze.cn/passport/token/beat/v2/
  sdk-version: 2
  x-tt-token: <355 字符>
  Content-Type: application/json
  body: {}

响应：HTTP 200
      {"message":"success","data":{"error_code":0}}
      Set-Cookie: 13 条
```

下发的 Cookie 名称与桌面端 `AUTH_COOKIE_NAMES` 白名单**完全一致**：

```text
odin_tt, uid_tt, uid_tt_ss, sid_guard, uid_tt, uid_tt_ss,
sid_tt, sessionid, sessionid_ss, session_tlb_tag,
is_staff_user, has_biz_token, session_tlb_tag
```

其中 `sessionid` / `sessionid_ss` / `sid_tt` / `sid_guard` 正是插件调用 `coze_claw` 所需的会话主 Cookie，也全部是 HttpOnly——**这正是必须走 token beat 而非读 `document.cookie` 的原因**。

### 3. Cookie 有效性校验

用上述 13 条 Cookie 调：

```text
GET https://www.coze.cn/passport/account/info/v2/
Cookie: <13 条>

响应：HTTP 200
      {"message":"success","data":{...}}
      data.sec_user_id 非空，长度 76
      data.user_id / data.screen_name 均存在
      data 键 20+：app_id, avatar_url, device_id, email, mobile, ...
```

`sec_user_id` 长度 76 与豆包插件的同类判据一致，可作为插件侧的登录态判据。

### 4. 续期闭环（用户核心要求）

**步骤 1**：带会话 Cookie 调 token beat

```text
POST /passport/token/beat/v2/
  sdk-version: 2
  Cookie: <13 条>

响应：HTTP 200
      message=success
      x-tt-token 响应头存在，长度 355（新 token）
      Set-Cookie: 0 条
```

**步骤 2**：用新 token 再换 Cookie

```text
POST /passport/token/beat/v2/
  sdk-version: 2
  x-tt-token: <新 355 字符>

响应：HTTP 200
      Set-Cookie: 13 条（与首次同名同量）
```

**步骤 3**：用第二轮 Cookie 再验证登录态

```text
GET /passport/account/info/v2/
Cookie: <第二轮 13 条>

响应：HTTP 200，data.sec_user_id 非空
```

**闭环成立**：`Cookie → 新 x-tt-token → 新 Cookie → 仍有效`。插件可实现无限滚动续期，不需要用户反复授权，也不存在豆包那种「Cookie 快照 30 天硬失效」的问题。

## 关键实现提示（给 TASK-002）

1. **必须用 `http.Client` 手动管理 Cookie**：Go 的 `cookiejar` 默认按域名存，但 token beat 的响应 Cookie 含重复名（`uid_tt` / `uid_tt_ss` / `session_tlb_tag` 各出现两次，分别对应不同 path/domain），落盘时要保留完整属性，不能简单覆盖。
2. **`sdk-version: 2` 必须带**，且 `Content-Type: application/json`、body 为 `{}`。
3. **token 只有 355 字符量级**，可安全放在回调 URL 的查询参数里；但仍需 `encodeURIComponent`。
4. **`state` 必须一次性消费**：本次验证服务已验证重放会被拒（`used` 标记）。
5. **续期建议**：watchdog 每 N 小时执行「带 Cookie 取新 token → 换新 Cookie → 验证」一轮；`step1` 若直接下发 `Set-Cookie`（本次为 0 条）则可省去 `step2`，实现上应同时兼容两种形态。
