### 2.6 真实免费账号端到端（T1-4，关闭 GAP-001 / GAP-002）

用真实 GitHub **免费**账号完成设备码授权后逐项实测（凭据原值不回显）：

| # | 验证项 | 结果 | 结论 |
|---|---|---|---|
| 1 | 设备码换 GitHub token | `200`，`token_len=40` | Device Flow 链路真实可用 |
| 2 | `copilot_internal/v2/token` 交换 | `200`，含 `token` + `expires_at` + `endpoints` | **GAP-001 PASS** |
| 3 | 账号档位 | `sku=free_limited_copilot`，`chat_enabled=true` | **免费账号可换取内部令牌** |
| 4 | 免费额度快照 | `chat: 200/200`、`completions: 1963/2000`、`premium_interactions: 0/0` | 额度可读 |
| 5 | 额度端点认证方式 | GitHub token `200`；Copilot token `401` | **必须用 GitHub token**（与 `quota.go` 实现一致） |
| 6 | `/models` 模型发现 | `200`，57 个模型 | 模型列表可用 |
| 7 | `/chat/completions` 非流式 | `200`，`content="PONG"`，`finish_reason=stop` | 推理可用 |
| 8 | `/chat/completions` 流式 | `200`，`text/event-stream`，11 帧，见 `[DONE]` | SSE 契约正确 |
| 9 | `endpoints.api` 实际取值 | `https://api.individual.githubcopilot.com` | **与硬推导默认值不同 → GAP-002 需消费** |
| 10 | 双 base URL 对照 | `api.individual.githubcopilot.com` 与 `api.githubcopilot.com` 均 `200` | 两个主机都可用 |

**GAP-001 结论：PASS** —— Copilot Free 账号可完整走通「Device Flow → Copilot 令牌 → 模型发现 → 推理」，插件对免费账号开放入口成立。

**GAP-002 结论：已关闭** —— 上游返回的 `endpoints.api` 真实存在且与按账号类型硬推导的默认值不同（`api.individual...` vs `api.githubcopilot.com`），已按需求文档要求改为「存在则以响应字段为准」：新增 `StoredAuth.APIEndpoint` 持久化，`resolveCopilotBaseURL` 优先级调整为「配置 base_url > endpoints.api > 按类型推导」。

## 三、未覆盖与诚实边界

1. **未在 CPA 宿主内加载插件跑通完整链路**：2.6 的实测是用等价 HTTP 请求直连上游验证协议契约，**未**在真实 CPA 实例中加载 `.so` 走宿主 RPC 桥。宿主内端到端属 CYCLE-2 / CYCLE-4 范围。
2. **`GAP-003`（GitHub 风控边界）仍未关闭**：单账号低频实测无法暴露限速 / 封号边界，需生产灰度观察。
3. **指纹头有效性已间接验证**：2.6 的推理与模型请求均带完整指纹头并返回 `200`，说明当前取值被上游接受；但上游收紧策略时会失效，需持续跟踪。
