## 四、过程中的真实故障与处置（重要）

### 4.1 registry 空 artifacts 导致源整体被拒（已修复，非本轮引入的最终态）

本轮侦察阶段曾向 `registry.json` 提前写入 copilot 条目，其 `install.artifacts` 为空数组。
CPA 校验 `direct` 安装类型要求至少一个 artifact，导致**整个 registry 源被拒绝**：

```
source_errors: plugins[8]: direct install requires at least one artifact
```

后果：所有插件的 `plugin-store install` 均返回 `plugin_not_found`。

并行会话以提交 `10a1f2f` 移除了该占位条目，恢复源可用性。本轮随后按发布 skill
Step 11 的正确语义处理：**registry 条目与 artifacts 由 `publish-assets.py` 一次性原子写入**，
本地补齐条目后立即填充 artifacts 才提交推送，避免「新 version + 空 artifacts」中间态进入远端。

**该事故与项目 skill 的既有条款完全吻合**：`project-cpa-workbuddy-plugin-release-rules`
Step 1 明确「本步禁止提前修改 `registry.json.version`」，registry 的 version 与 artifacts
必须在 Step 11 由 `publish-assets.py` 原子更新。本轮已纠正并遵循。

### 4.2 首次 accounts/panel 404 属加载时序竞态（非缺陷）

install 返回后立即请求 accounts/panel 得到 404，同一端点复测即 200；日志显示
`plugin loaded` 与 `plugin registered` 时间戳与 install 响应同一秒。判定为加载时序竞态，
与踩坑 40 的「瞬时抖动先复测」判据一致。对照组 zcode 在同一时刻同样返回 404 后复测 200。
