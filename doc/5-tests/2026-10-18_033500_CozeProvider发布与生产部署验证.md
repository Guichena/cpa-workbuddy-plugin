## 2. 发布过程中修复的三个真实缺陷

### 2.1 授权脚本被 HTML 实体化（0.1.0 → 0.1.3，三次迭代）

**根因在宿主侧**：宿主回写 `ManagementResponse.Body` 时会再做一次带 HTML 转义的
JSON 序列化。

实测证据（生产 0.1.2，用 `/renew` 的错误文案回显特殊字符）：

```text
入参 auth_id = x<y>z'w
响应        = {"error":"账号不存在：x&lt;y&gt;z&#39;w","ok":false}
```

三次迭代：

| 版本 | 尝试 | 结果 |
|---|---|---|
| 0.1.1 | 关掉 `okEnvelope` 的 `SetEscapeHTML` | ❌ 转义发生在更早的 payload 层 |
| 0.1.2 | 改 `handleLoginStartFromPanel` 的 payload 编码 | ❌ 转义发生在宿主回写层 |
| 0.1.3 | **脚本以 base64 下发**，面板 `atob` + `TextDecoder` 解码 | ✅ 生产实测 0 处实体 |

生产 0.1.3 实测：`gt_entity=0`、`quot_entity=0`、`encoding=base64`；
解码后脚本 550 字节，`=>` / `credentials:'include'` / `__CPA_ORIGIN__` /
`#token=` / state 全部正确。

### 2.2 CI 误带入 qwenwork 矩阵项（已修复）

整文件暂存 `build.yml` 时把并行会话未提交源码的 qwenwork CI 配置一并带上，
CI checkout 后找不到 `qwenwork/go.mod` → `Test (qwenwork)` 在 setup-go 失败
→ 所有插件的 Release job 被跳过。已单独提交移除。

### 2.3 tag 推送被 workflows 权限拒绝（已修复）

```text
! [remote rejected] coze-provider-v0.1.0 -> coze-provider-v0.1.0
  (refusing to allow a GitHub App to create or update workflow
   `.github/workflows/build.yml` without `workflows` permission)
```

默认 `GITHUB_TOKEN` 没有 `workflows` 权限；coze 是本仓库首个「插件提交本身
含 workflow 改动」的发布，因此第一次踩到。改为由 `gh release create`
用 API 建 tag（不经 `git push`），已实测通过。
