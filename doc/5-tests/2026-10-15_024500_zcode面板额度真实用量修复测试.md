## 三、改动与断言

### 改动

- `zcode/quota.go`：`fetchAccountQuota` 改为**主走 balance**（`billing/balance?app_version=<v>`，携带 `X-Platform` / `X-Device-Mid` / `X-ZCode-App-Version`），失败回退 current；新增 `fetchQuotaFromEndpoint`、`balanceEndpoint`、`balanceURLForTest`；快照新增 `total_used` / `total_remain` / `has_usage` / `source`，entitlement 新增 `used_units` / `remaining_units` / `available_units` / `has_usage`。
- `zcode/panel.html`：`quotaHTML` 按「剩余/授予」渲染进度条（≤30% 黄 / ≤10% 红），无用量通道标注「暂未取到用量」；汇总区新增「今日剩余合计」。
- `zcode/management.go`：新增 `friendlyClaimError()` 翻译上游英文错误；面板「未开放」类提示降级为 warn。

### 断言（`zcode/quota_test.go`）

| 用例 | 断言 |
| --- | --- |
| `TestFetchAccountQuota_ParsesBalanceUsage` | balance 主通道必须携带设备三头 + `app_version`；`Source=="balance"`、`HasUsage==true`；`TotalUsed==1700000`、`TotalRemain==6300000`；逐 entitlement 用量并入正确 |
| `TestFetchAccountQuota_ParsesPlan` | balance 返回 3001 时自动回退 current，`Source=="current"`、`HasUsage==false`、`TotalRemain==TotalGrant==8000000` |
| `TestFriendlyClaimError` | `no permission` / `already exists` / `target not found` 映射为中文；未知错误保留原文 |
| `TestHandleQuotaQuery_AllAccounts` | 双通道均不可达时逐账号返回 error 字段，不 panic |
| `TestQuotaForAccount_Caches` | 双通道注入同一 mock 后缓存命中与 force 绕过行为不变 |

## 六、领取失败提示实测

- 上游 `billing/preview` 对全部 7 个账号返回 `code:0` + `plans:[]`（换 `app_version` / `platform` 无关），claim 业务层返回英文 `no permission`。
- 修复后 `friendlyClaimError` 将其翻译为「当前上游未开放 Start Plan 领取（活动暂不可领取），请稍后重试或在 ZCode 客户端内领取」，面板以 warn 级提示展示。
