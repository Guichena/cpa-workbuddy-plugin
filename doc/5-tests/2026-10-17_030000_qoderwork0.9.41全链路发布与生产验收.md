## 6. ⚠️ 既有现象登记：`Signature invalid`（非本轮引入）

生产日志存在大量 `[qoderwork] callModelsAPI: upstream status 403, body: {"code":"101","message":"Signature invalid"}`。**经完整取证判定为既有现象，与本次指纹改动无关**：

| 判据 | 证据 |
| --- | --- |
| **时间早于部署** | 最早出现 `2026/10/16 16:00:00`（`[qoder-ai]`），我的部署在 `01:27:16`（10-17），**早数小时** |
| **跨 12 小时持续** | 16:00 起各小时均有（16h:266、20h:1332、23h:7964、01h:3983…） |
| **部署前后对比** | 部署前 01:00~01:27 有 **810** 次；部署后仍有（属同一既有现象延续） |
| **qoder-ai 同现象** | `[qoder-ai]` **10578** 次 vs `[qoderwork]` 3435 次——qoder-ai **未做任何改动**却同样大量出现 |
| **代码事实** | 签名式 `md5(payloadB64 + cosyKey + date + body + pathSig)`——**machineID/machineToken/machineType 不参与签名**，改指纹在数学上不可能改变签名结果 |
| **影响面** | 仅 `callModelsAPI`（动态模型发现）；推理链路正常（`test-active` 通过鉴权、用量记录持续） |
| **对照插件** | `[workbuddy]`/`[traework]`/`[zcode]` 均为 **0** 次，说明是 Qoder 系特有（CN 域 `callModelsAPI` 签名契约变化） |

**处置**：登记为独立待查项（P2），需单独立项排查 Qoder 系 `callModelsAPI` 的 COSY 签名契约是否发生上游变更；**不属于本轮 CYCLE-01 范围**。
