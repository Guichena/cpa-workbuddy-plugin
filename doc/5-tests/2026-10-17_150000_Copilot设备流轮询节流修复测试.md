# Copilot 设备流轮询节流修复测试

- 测试时间：2026-10-17 15:00:00（北京时间）
- 关联 Bug：BUG-COPILOT-DEVICEFLOW-SLOWDOWN-20261017（`doc/4-bugs/2026-10-17_150000_Copilot设备流轮询过快触发slow_down致授权成功后长时间不落盘根因诊断.md`）
- 被测对象：`copilot/oauth.go`、`copilot/main_test.go`

## 一、测试范围

1. 间隔窗口内不访问上游：未到 `nextPollAt` 时连续轮询必须返回 `pending` 且上游调用次数为 0。
2. 窗口过后真实访问上游：推进窗口后必须产生 1 次上游调用。
3. `slow_down` 间隔采纳：上游返回 `interval=30` 时，会话 `Interval` 变为 30 秒且 `nextPollAt` 被推后。
4. 回归：原有设备码全链路（申请 → pending → success → 落盘）不得被节流破坏。

## 四、哨兵变异（判别力验证）

| 变异 | 预期 | 实测 |
| --- | --- | --- |
| 删除 `pollDeviceLogin` 中的节流判断 | `ThrottlesWithinInterval` 失败 | FAIL：`upstream calls=3, want 0 within interval window` |
| 删除 `slow_down` 分支中的 `applySlowDown` + `nextPollAt` 推后 | `AdoptsSlowDownInterval` 失败 | FAIL：`interval=5s, want 30s` |

两处变异均被对应用例精确捕获；恢复原代码后全绿。

## 五、上游契约实测（生产服务器）

```
interval_from_github = 5
3s 间隔轮询：authorization_pending → slow_down(10) → slow_down(15) → slow_down(20) → slow_down(25) → slow_down(30)
5s 间隔轮询：连续 4 次 authorization_pending，无 slow_down
```

确认 GitHub 设备流以 `interval` 为最小轮询间隔，快于该值会进入 `slow_down` 阶梯。
