# 全插件签到节奏统一为每 4 小时实施总览

- 编号：IMPL-CHECKIN-EVERY-4H-20261015
- 触发：用户裁定（2026-10-15 03:00）「我们先把所有支持签到的插件改成每4小时尝试签到一次」
- 状态：已完成（本地验证全绿 + 四插件发布）

## 1. 当前计划最终方案简要说明

把 5 个支持签到的插件统一为「本地时间每 4 小时一次」：qoderwork / qoder-ai 的 `checkinHours` 由 `[10,22]` 恢复为 `[0,4,8,12,16,20]` 并**删除因此退化为死代码的 `shouldRunCheckinNow` 门控**；workbuddy / workbuddy-ai / traework 的后端调度本就已是每 4 小时，仅修正其面板与文档中错标为 `09:00/21:00` 的文案漂移。

## 2. agent 对问题的理解

- **问题/目标**：当前 5 个签到插件的节奏不一致——workbuddy / workbuddy-ai / traework 为每 4 小时六槽，qoderwork / qoder-ai 为每日 10:00 与 22:00 两槽。用户要求全部统一为每 4 小时一次。
- **本轮范围**：qoderwork、qoder-ai 的调度常量与门控；workbuddy、traework 的面板文案；相关 README / architecture 文档；四插件的测试与 CHANGELOG。
- **非范围**：签到协议本身（上游端点、请求头、成功判定、风控重试）；keepalive token 刷新节奏（保持每 4 小时不变）；`checkin_auto` 开关语义；zcode / cursor（不支持签到）；调度器路由逻辑（属并行会话在途改动）。
- **当前优先闭环**：四插件隔离环境 build/vet/test 全绿 + 面板内联 JS 真实执行无 ReferenceError + 文档落盘。
- **关键假设**：`shouldRunCheckinNow` 在两表取值一致后即为恒真死代码，应当删除而非保留（保留会形成"看似有防护实则无效果"的误导）。

## 3. 关键耦合（必须一并处理）

1. **签到与 keepalive 共用同一个 `schedulerLoop` 定时器**：`nextCheckinTime` 取 `checkinHours ∪ keepaliveHours` 并集唤醒。当两表取值不同（历史 `[10,22]` vs 六槽）时，共享定时器会在纯保活时刻（04:00/16:00 等）唤醒并误触发签到，故当时新增了 `shouldRunCheckinNow` 门控。本轮把签到表恢复为六槽后，并集恒等于签到表本身，门控的判定条件对每次唤醒都返回 true —— 退化为恒真死代码。
2. **`panel.html` 经 `go:embed` 进二进制**：四个插件的面板文案改动都会打进 `.so`，因此文案修正必须随版本发布才能在生效，不能只改仓库。
3. **`schedule` 字段与面板文案是同一事实的两处投影**：`panel.go` 的 `schedule` 与 `panel.html` 的副标题/开关提示必须同步，否则面板自身展示矛盾。

## 5. 验证步骤与通过标准

- **真实测试入口**：`python scripts/cgo-shim-build.py <plugin>`（build + vet + test），四插件全绿。
- **隔离环境验证**：因工作树存在 20 个并行会话文件（调度器路由反转），必须用 `git worktree add --detach HEAD` 建立「纯 HEAD + 本轮文件」环境验证，模拟 CI 构建对象。
- **面板验证**：`node --check` 校验内联 JS 语法 + 既有 vm + DOM 桩回归脚本真实执行（捕获 ReferenceError，`node --check` 抓不到未定义标识符）。
- **通过标准**：四插件隔离环境 all green；面板脚本 PASS；`shouldRunCheckinNow` 在 Go 代码中零残留引用。
